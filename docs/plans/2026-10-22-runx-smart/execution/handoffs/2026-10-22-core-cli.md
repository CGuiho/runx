## Required behavior

`runx smart` (Cobra subcommand, flags in full long form only):

- Bare `runx smart` prints byte-identical output to `runx list` for the same
  `--cwd`, `--config`, `--format`, `--verbose`.
- `runx smart <selector> [--] [child args...]` behaves exactly like
  `runx run <selector> [--] [child args...]`: confirmation handling, `--yes`,
  `--dry-run`, JSON plan, child argument forwarding after the selector, and
  exit-code preservation.
- Flags parse natively and stop at the first positional
  (`command.Flags().SetInterspersed(false)`), so child flags after the selector
  are forwarded untouched.
- `runx smart -h`/`--help`, `--help-tree`, `--help-tree-depth`, `--help-docs`
  describe the `smart` command itself. `-v`/`--version` stays top-level only.
- Do not duplicate list or run semantics: extract the existing bodies (for
  example `runCatalogList` and `runCatalogRun`) from `newListCommand` and
  `newRunCommand`, and call them from both the canonical commands and `smart`.
- Short description, for example: "List the catalog, or run a command by
  selector."

`rxs` launcher (rename, not a copy — `git mv cmd/rx cmd/rxs`):

- Diagnostics say `rxs launcher:` instead of `rx launcher:`.
- No arguments: run the payload `smart` subcommand.
- Root passthrough flags forward to the payload root unchanged: `-v`,
  `--version`, `-h`, `--help`, `--help-tree`, `--help-docs`,
  `--help-tree-depth`, `--help-tree-depth=<n>`, `--help-tree-global-flags`,
  and a single `--color`.
- Every other argument list forwards as `smart <args>` so the payload owns the
  translation (`--format json` lists, `--cwd X build` runs, `build --foo` runs
  with a child argument).
- Preserve pointer resolution, fallback payload behavior, and exit-code
  delegation from the current `cmd/rx`.
- Update `cmd/rx/main_test.go` expectations to the new forwarding contract
  (root passthrough unchanged, everything else prefixed with `smart`).
